## **3. Социальное взаимодействие и Финальный UX**

### **3.1. Реализация отображения ссылок в соцсетях (SCRUM-43)**

Чтобы при отправке ссылки в Telegram или WhatsApp пользователь видел красивое превью (картинку, заголовок и описание списка).

**Технические требования:**

1. **Интеграция OpenGraph тегов:** Добавление в index.html динамических мета-тегов.
2. **Динамическое управление тегами:** Использование библиотеки react-helmet-async (или аналога) для того, чтобы подставлять в og:title имя владельца и название конкретного списка желаний.
3. **Набор обязательных тегов:**
    - og:title — «Вишлист: [Название списка]»
    - og:description — «Посмотри мои желания и забронируй подарок!»
    - *Дополнительно:* Настройка фиксированного og:image (логотип или обложка сервиса), который будет подтягиваться при вставке ссылки.

### **3.2. Механизм отмены бронирования для гостей (SCRUM-72)**

Реализация возможности для гостя отменить свою бронь без создания аккаунта.

**Логика взаимодействия:**

1. **LocalStorage:** При успешном бронировании (POST /reserve) фронтенд сохраняет в браузере гостя (LocalStorage) объект с данными: wishlist_item_id и reservation_token (уникальный ключ брони, выданный бэкендом).
2. **Проверка прав:** На публичной странице списка фронтенд сопоставляет ID товаров из списка с данными в LocalStorage.
3. **Интерфейс:** Если ID товара найден в памяти браузера, вместо плашки «Занято [Имя]» гость видит кнопку **«Отменить мою бронь»**.
4. **Бэкенд-эндпоинт:** Создание публичного метода DELETE /api/v1/public/reservations/{reservation_id}, который требует передачи reservation_token в заголовке или теле запроса. Бронь удаляется только при совпадении токена.

---

### **3.3. Адаптация интерфейса под мобильные устройства (SCRUM-42)**

Финальная доработка верстки для идеального отображения на смартфонах.

**Ключевые точки адаптации:**

1. **Сетка товаров:** Переход с 3-4 колонок на десктопе в 1 колонку на мобильных устройствах (разрешение < 480px).
2. **Модальные окна:** Окно бронирования и форма регистрации должны занимать 95% ширины экрана на мобилках, чтобы по кнопкам и полям ввода было легко попадать пальцем.
3. **Навигация:** Адаптация шапки сайта (мобильное меню или упрощенный вид).
4. **Кнопка «Поделиться»:** Проверка работы API копирования ссылки (Clipboard API) на мобильных браузерах (Safari/Chrome).

---

### **3.4. Настройка внешних сервисов (Production Config) (SCRUM-41)**

Техническая конфигурация уже существующих сервисов для работы на сервере.

1. **SMTP:** Переключение с отладочных настроек на реальный сервер (порт 465/587, включение SSL/TLS, использование пароля приложения).
2. **Парсинг (Scraping):**
    - Добавление заголовков User-Agent реального браузера в httpx клиент, чтобы избежать блокировок со стороны Wildberries при запросах с IP дата-центра.
    - Настройка увеличенных таймаутов для сетевых запросов в условиях нестабильного соединения на сервере.
